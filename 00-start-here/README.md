# 00 — Start Here

## Purpose

This module explains how to use the **GitHub Professional Operator — AI-First Founder Crash Course** as an actual operating environment rather than a passive reading course.

The repository is simultaneously:

1. a working GitHub environment;
2. a professional GitHub curriculum;
3. a public case study of Student #1, David;
4. a reusable AI-coaching system for future learners.

The central teaching rule is simple:

> **Learn GitHub by operating GitHub.**

## End State

A graduate should be able to design, operate, audit and improve a professional GitHub-based environment and confidently answer:

- Why does this work exist?
- Where is the authoritative task or decision?
- Which branch contains the proposed change?
- What changed and who or which agent changed it?
- What evidence proves the change is safe?
- What is waiting, blocked, under review or complete?
- What version contains the accepted change?
- Which automation or agent executed?
- What belongs in GitHub and what should integrate with another system instead?

## The Course Backbone

The core professional workflow is:

```text
Issue
→ issue-linked branch
→ focused commits
→ Pull Request
→ checks / review
→ merge
→ release / deployment when appropriate
→ durable history
```

For portfolio planning:

```text
Issues + Pull Requests
→ GitHub Project
→ Table / Board / Roadmap / filtered views
```

For AI-assisted execution:

```text
human / ChatGPT Web
→ governed Issue
→ deterministic trigger or direct assignment
→ coding agent / AI workflow
→ branch + commit + PR
→ checks / review
→ merge
```

## Learning Method

Each substantial topic should follow:

```text
concept
→ why it matters to an operator
→ real repository example
→ hands-on task
→ checkpoint
→ evidence
→ progress update
→ reader-surface update when material
```

Reading is exposure. Performing and explaining are evidence.

## Evidence Standard

A learner has not mastered a capability merely because:

- the coach explained it;
- an agent performed it;
- a workflow exists;
- a setting is enabled;
- an integration is installed.

Use this model:

```text
seen
≠
understood
≠
performed with help
≠
performed unaided
≠
can diagnose / improve professionally
```

## First Operating Rules

1. Read root `AGENTS.md` before substantive agent work.
2. Start substantive repository changes from an Issue.
3. Do not work directly on `main`.
4. Treat a PR as the acceptance/review gate.
5. Verify actual capability; do not infer it from installation or marketing.
6. Keep secrets out of repository files and chat transcripts.
7. Search GitHub-native capability before building duplicate infrastructure.
8. Use canonical files for truth and Wiki/Pages for navigation/publishing.
9. Keep reader-facing documentation synchronised when material course/student state changes.
10. Preserve mistakes and corrections as learning evidence.

## Start the Course

Recommended sequence for a new learner:

1. Read this page.
2. Complete a baseline diagnostic.
3. Read Module 01.
4. Use Module 02 to create the first governed Issue.
5. Work through the branch/PR loop in Module 03.
6. Add the work to a Project in Module 04.
7. Automate a safe repeated step in Module 05.
8. Learn release/version discipline in Module 06.
9. Build the knowledge/publishing model in Module 07.
10. Apply security/governance controls in Module 08.
11. Delegate safely to AI agents in Module 09.
12. Decide GitHub/system boundaries in Module 10.
