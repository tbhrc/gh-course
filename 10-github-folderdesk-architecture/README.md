# 10 — GitHub × FolderDesk Architecture

## Objective

Decide what GitHub should own, what FolderDesk should own, and what should integrate between them.

## Decision Framework

For each capability classify it as:

- Keep in GitHub
- Keep in FolderDesk
- Integrate
- Retire / replace

## Principles

- Use GitHub where it already provides mature native capability.
- Keep FolderDesk focused on broader file-first operating needs beyond software development.
- Avoid duplicate systems of record.
- Apply KISSS: Keep It Stupid Simple and Short.

## Practical Exercise

Map the current FolderDesk task, change, release, audit and agent workflows against native GitHub capabilities and identify duplication.
