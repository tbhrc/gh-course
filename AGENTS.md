# Agent Contract — GitHub Course

## Purpose

`tbhrc/gh-course` is a **public learning and safe proving ground** for GitHub operation.

It owns:
- public teaching material;
- bounded GitHub learning experiments;
- course-specific examples and exercises.

It does **not** own:
- reusable TBHRC Skills;
- business/domain truth;
- shared credentials or secret replication;
- production AI orchestration;
- external technology research;
- production runtime infrastructure.

## Authorised TBHRC agent bootstrap

Before substantive repository work, use the current canonical private Skills when accessible:

1. `tbhrc/skills/human-ai-operations-map`
2. `tbhrc/skills/github-power-user`
3. `tbhrc/skills/github-agent-workflow`

Do not copy those Skill bodies into this public repository.

Public learners must still be able to understand every course module without private access.

## Change workflow

For substantive course changes:

```text
Issue
→ issue-linked branch
→ focused change
→ verify
→ Pull Request
→ review/checks where useful
→ merge
→ close
```

Use the lowest sufficient ceremony. Do not create automation, custom agents, dashboards or publishing systems merely because GitHub supports them.

## Research escalation reflex

When a course experiment or operational example exposes a recurring failure, workaround, missing tool or broader capability limitation:

```text
contain the immediate safe problem if necessary
→ ask whether it is structurally broader
→ if yes, route external/tool research to tbhrc/research
→ use canonical open-source-operations-radar
→ research symptom → workflow → capability → platform/system
→ compare native / existing / open-source / paid options
→ test only qualified candidates in the correct owner
→ return benchmark evidence
→ promote reusable HOW to tbhrc/skills when proven
```

Research is not implementation ownership. AI Engine is used only when a qualified test genuinely needs privileged VPS/Mac/local-runtime access.

## Repository hygiene

- No local `skills/` directory.
- No committed credentials or private company/client/candidate data.
- No secret-bridging workflow.
- No production agent dispatcher.
- No generated Wiki/Pages/CMS state unless a future teaching Issue proves a real need.
- No duplicated learner-state framework until a real multi-student requirement exists.
- Do not restore the pre-reset architecture wholesale. Git history is the archive.

## Teaching standard

Every module should answer:
1. What is it?
2. Why does an operator care?
3. What can go wrong?
4. What is the smallest practical exercise?
5. What evidence proves understanding?

Prefer clear operator language over developer jargon.
