# Course Architecture

## One job

This repository teaches and safely proves GitHub operating concepts.

```text
PUBLIC COURSE
= teaching + exercises + bounded experiments
```

Everything else routes outward to its real owner.

## TBHRC ecosystem position

```text
                         tbhrc/skills
                    reusable HOW / Skills
                           ↑      ↓
                           │      │
TBHRC work ────────────────┘      └──────── owning repositories
   │                                      / systems
   │
   ├─ learning / GitHub proving ──→ tbhrc/gh-course
   │
   └─ recurring tool/capability gap
                   ↓
             tbhrc/research
                   ↓
        discover / compare / prove
                   ↓
           qualified owner test
                   ↓
      normal capability or AI Engine
                   ↓
               benchmark
                   ↓
        promote proven capability
```

## Ownership table

| Need | Owner |
|---|---|
| Public GitHub teaching | `tbhrc/gh-course` |
| Reusable operating method | `tbhrc/skills` |
| External OSS/tool/platform research | `tbhrc/research` |
| Business/product truth | relevant domain repository/system |
| Privileged VPS/Mac/local runtime bridge | `tbhrc/ai-engine` only when required |
| Private/client files | approved private file store |

## Why this repository is intentionally small

The previous course accumulated Skills, agent dispatchers, secret bridges, generated publishing state, benchmark systems, student-state machinery and overlapping governance. That made the course itself harder to understand than the GitHub concepts it was teaching.

The reset uses a simpler rule:

> **Teach the concept here. Operate the real capability in its real owner.**

Git history preserves the old experiments for provenance without forcing them into the current learning surface.
