# Curriculum

## Learning sequence

| # | Module | Learn | Prove |
|---:|---|---|---|
| 0 | Start Here | Course mental model | Explain what this repo owns and does not own |
| 1 | Foundations | Repo, commit, branch, clone/fork basics | Trace a change from working tree to commit |
| 2 | Issues | Durable work definition | Write one actionable Issue with acceptance criteria |
| 3 | Branches & Pull Requests | Isolation, review, merge | Complete one Issue → branch → PR → merge cycle |
| 4 | Projects | Portfolio visibility | Put Issues/PRs into one useful Project view |
| 5 | Actions & Runners | Event → workflow → job → runner → steps | Explain where a job physically executes |
| 6 | Security & Governance | Least privilege and protected change | Identify unsafe secret/runner/permission patterns |
| 7 | AI Agents & Skills | Instructions, Skills, agents, MCP, hooks | Choose the smallest agentic GitHub mechanism for a problem |
| 8 | Research & Capability Discovery | Problem-to-platform thinking | Expand one recurring local problem into a research question |
| 9 | Capstone | End-to-end operation | Deliver one verified improvement and explain the evidence |

## Progress rule

Do not equate reading with mastery. A learner advances when they can explain the concept and demonstrate the relevant GitHub action or evidence.

## Current-facts rule

GitHub features, plans, previews and AI surfaces change. For volatile claims, verify current official GitHub documentation or live repository behaviour rather than treating course prose as timeless API truth.
