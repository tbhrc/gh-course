# GitHub Professional Operator

A practical, AI-first course for learning and reproducing **ARC**: the Skills-first GitHub operating ecosystem developed through real TBHRC operations.

> This repository is a **public learning and proving ground**. It teaches the architecture and methodology. It is not the live TBHRC Skill Bank, business canon, shared secret store, production control plane or future ARC deployment package.

## Why this course exists

GitHub Course is not an abstract curriculum designed first and implemented later.

It is where the current ecosystem began.

David started the course with a hunch that GitHub was far more powerful than a code repository. As each capability was learned, it was immediately tested and applied to real operations. Issues became durable work objects. Pull Requests became review boundaries. Skills became reusable operating intelligence. GitHub became the human + AI operating desk. That practical learning accelerated the migration away from FolderDesk and produced the architecture now used across the estate.

Read [The Origin Story](ORIGIN-STORY.md) for the preserved narrative.

## The mission now

The course has moved from **discovering GitHub** to **teaching a reproducible operating system**.

A student should not wander through random GitHub features. They should learn the smallest set of concepts, in the correct order, needed to understand and reproduce ARC:

```text
problem / opportunity
→ Skills first
→ correct owner / repository
→ Issue / branch / PR
→ authorised agent execution
→ Research when a recurring capability gap appears
→ AI Engine only for genuine privileged runtime gaps
→ verify real state
→ durable GitHub evidence
→ reusable learning back to Skills
```

## Course path

| Module | Outcome |
|---|---|
| 01 — Foundations | Understand repositories, commits, branches and GitHub as an operating surface. |
| 02 — Issues | Turn work into durable, executable problem statements. |
| 03 — Branches & Pull Requests | Change safely through isolated work, review and merge. |
| 04 — Projects | Coordinate work across Issues and PRs without creating a second source of truth. |
| 05 — Actions & Runners | Understand automation, GitHub-hosted runners and self-hosted execution. |
| 06 — Security & Governance | Apply least privilege, protected change paths and secret-safe operation. |
| 07 — AI Agents & Skills | Understand agents, instructions, Skills, MCP and agent-ready repositories. |
| 08 — Research & Capability Discovery | Turn recurring friction into broader tool/platform research before inventing infrastructure. |
| 09 — Capstone | Reproduce one real ARC operating loop from problem to verified outcome. |

## Course versus ARC

```text
GitHub Course
= HOW TO LEARN + UNDERSTAND + REPRODUCE THE SYSTEM

ARC
= THE REPRODUCIBLE SYSTEM / DEPLOYMENT BLUEPRINT ITSELF
```

The future dedicated ARC repository will own the deployable ecosystem manifest: required repositories/capabilities, bootstrap order, configuration contracts, safe placeholders for secrets, verification, portability and redeployment guidance.

The Course teaches that system without becoming another copy of it.

## TBHRC operator integration

Public learners can complete this course without private TBHRC access. Authorised TBHRC agents additionally use the canonical private operating layer:

```text
human-ai-operations-map
→ github-power-user
→ github-agent-workflow
→ owning repository/system
```

When a local problem exposes a broader recurring tooling or capability gap:

```text
local problem
→ tbhrc/research
→ open-source-operations-radar
→ qualified test
→ owning repository/runtime
→ benchmark
→ promote proven capability
```

Canonical reusable HOW remains in `tbhrc/skills`; external research/proving evidence remains in `tbhrc/research`; privileged runtime infrastructure remains in `tbhrc/ai-engine` only where required.

## Design principles

- **Skills first.** Learn the reusable method before improvising process.
- **One thing, one owner.** Do not create parallel truth.
- **Learn by operating real GitHub objects.**
- **Research recurring friction.** A small problem may reveal a much bigger reusable capability opportunity.
- **Prefer the smallest native capability that works.**
- **Agents need tools.** Capability, permissions and execution routes matter as much as model intelligence.
- **Testing is not adoption.** Prove before promotion.
- **Git history is the archive.** The current course tree stays intentionally clear.
