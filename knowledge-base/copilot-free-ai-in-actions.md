# Copilot Free AI Inference Inside GitHub Actions

**Status:** operationally proven  
**Last verified:** 27 August 2026  
**Evidence:** Issue #45, Actions run `33076875845`

## Question

Can GitHub Copilot Free perform genuine AI work automatically from a GitHub Issue even though the Copilot cloud agent cannot be assigned on the Free plan?

## Verified answer

**Yes — for AI inference inside GitHub Actions via GitHub Copilot CLI.**

**No — for the autonomous Copilot cloud-agent Issue assignee.**

These are separate execution modes.

```text
COPILOT FREE

Available and proven:
Issue
→ GitHub Actions
→ Copilot CLI
→ Copilot AI inference
→ captured text output
→ deterministic Issue comment

Not available on Free:
Issue
→ assign copilot-swe-agent[bot]
→ autonomous cloud coding agent
→ agent branch / PR
```

## Live proof

Issue #45 was created with title prefix `[copilot-free-ai]` after workflow `.github/workflows/copilot-free-ai-smoke.yml` was merged to `main`.

GitHub created Actions run `33076875845`.

The run completed:

```text
✅ Check out repository
✅ Install GitHub Copilot CLI
✅ Build bounded prompt
✅ Run Copilot AI inference
✅ Post AI response to Issue
```

The AI response posted to Issue #45 correctly identified the repository purpose, the benchmark objective and the deterministic-vs-agentic distinction. It explicitly stated that the analysis was generated by Copilot AI inference rather than deterministic shell logic.

This is operational evidence of model inference because the workflow's shell logic only assembled context, launched Copilot CLI, captured its response and posted that response. The analytical prose was not prewritten in the workflow.

## Authentication model

The repository keeps the secret name:

```text
AGENT_DISPATCH_TOKEN
```

The underlying fine-grained GitHub PAT has user-level Copilot permissions including access to user Copilot requests.

Inside the Actions workflow the stored secret is mapped to the environment variable expected by Copilot CLI:

```yaml
env:
  COPILOT_GITHUB_TOKEN: ${{ secrets.AGENT_DISPATCH_TOKEN }}
```

Therefore:

```text
AGENT_DISPATCH_TOKEN
= repository Actions secret name

COPILOT_GITHUB_TOKEN
= runtime environment-variable name consumed by Copilot CLI
```

Do not rename or duplicate the repository secret merely because the consumer expects a different environment-variable name.


That request returned HTTP `403 Forbidden` on the Free plan.

Issue #45 instead tested:

```text

```

That succeeded.

So the correct model is:

```text
Copilot Free AI inference
≠ Copilot cloud coding agent
```

A plan can permit one and deny the other.

## Deterministic vs agentic boundary

In the successful run:

### Deterministic

- Issue event trigger;
- repository checkout;
- npm install;
- prompt assembly;
- environment-variable mapping;
- capturing stdout;
- posting the final comment.

### Agentic AI

- Copilot interpreting the supplied repository and Issue context;
- generating original analytical prose;
- explaining the distinction between deterministic Actions and model inference.

## Safe first-test pattern

For proving AI without granting write authority:

```text
Issue
→ deterministic workflow
→ assemble bounded context
→ Copilot CLI text inference
→ capture stdout
→ deterministic safe output
```

Keep the model from editing files, pushing commits or calling external services in the first benchmark. Expand permissions only after inference is proven and governance is clear.

## Operator lesson

Do not ask only:

> "Does this plan include Copilot?"

Ask:

> "Which Copilot execution mode is available on this plan?"

Evaluate separately:

1. interactive agent mode;
2. Copilot CLI inference;
3. Copilot CLI inside Actions;
4. GitHub Agentic Workflows;
5. Copilot cloud coding agent;
6. third-party partner agents such as Codex and Claude.

## Governing principle

> **Capability should be classified by execution mode and live evidence, not by product name alone.**
