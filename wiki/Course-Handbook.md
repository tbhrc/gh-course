# Course Handbook

This page explains how to use the GitHub Professional Operator course as a learner, coach or AI-assisted operator.

## Course Goal

The target is not to memorise GitHub features. The target is to become able to operate GitHub professionally and answer:

- What is changing?
- Why is it changing?
- Who or which agent changed it?
- What work is outstanding?
- What passed or failed?
- What is safe to merge?
- What version contains the change?
- What should happen next?

## Learn by Operating

Each substantial topic should move through:

```text
concept
→ operator value
→ live example
→ hands-on GitHub task
→ checkpoint
→ evidence
→ progress update
```

Reading a lesson does not equal mastery.

## Core Rules

### 1. Issue first

Every substantive repository change should begin with a governing Issue.

```text
Issue
→ issue-linked branch
→ focused commits
→ Pull Request
→ review/checks
→ merge
→ Issue closes
```

### 2. Preserve learning evidence

The course records:

- original understanding;
- misconceptions;
- corrections;
- partial recall;
- spontaneous insights;
- demonstrated ability;
- remaining mastery gaps.

### 3. Verify current GitHub behaviour

Do not rely on model memory for material current GitHub claims when authoritative evidence is available.

### 4. Use GitHub-native capability first

Before creating custom infrastructure, check whether GitHub already provides the capability.

## Wiki Role

This Wiki is the **reader-facing handbook and dashboard**.

The governed source for these Wiki pages lives under `wiki/` in the main repository. After approved changes merge, GitHub Actions publishes the pages to the separate Wiki Git repository.

That gives the course both:

- normal Issue/PR governance for Wiki source; and
- the convenient Wiki reading experience.
